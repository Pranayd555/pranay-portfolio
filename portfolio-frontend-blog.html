How I Built a Real-Time AI Chat Interface Inside a High-Performance Angular 21 Portfolio

A personal portfolio is no longer a static brochure. Mine streams AI responses over WebSockets, caches conversation history off the main thread, and renders immersive Three.js visuals — all while keeping the UI frame budget under control. This is the step-by-step story of how I wired it together.

Introduction & The Frontend Challenge

When I decided to embed an AI-powered chat assistant directly into my portfolio, I knew the bar was higher than dropping a third-party widget into a corner. Users expect instant feedback, token-by-token streaming that feels like ChatGPT, and a visual layer that matches the rest of the experience — not a jarring modal that tanks performance.

My goals were explicit from day one:

  • Real-time UI updates — render each streamed text chunk as it arrives, without waiting for the full response.
  • Non-blocking data operations — persist chat history without causing scroll jank or animation stutters.
  • Zero-lag rendering — minimize change detection work so the DOM only updates when state actually changes.
  • A jaw-dropping visual experience — WebGL particle systems and shader-driven backgrounds that coexist with live chat traffic.

The architecture I landed on splits concerns deliberately: NgRx owns long-lived portfolio section data (projects, skills, experience), while the chat layer uses Angular Signals for ephemeral, high-frequency state and a dedicated Web Worker for IndexedDB persistence. The result is a system that feels instantaneous even under load.

Phase 1: The Modern Angular Foundation (Angular 21, Signals, & OnPush)

I built this portfolio on Angular 21 with zoneless change detection enabled globally. Zone.js was the right tool for a decade, but for a chat UI that receives dozens of WebSocket events per second, I wanted Angular to update the DOM only when signals change — not on every async callback Zone.js happens to patch.

Zoneless + NgRx at the Root

My app.config.ts registers zoneless detection alongside the NgRx store, effects, and devtools. This is the foundation everything else sits on: 

src/app/app.config.tsexport const appConfig: ApplicationConfig = {

OnPush Everywhere It Matters

I apply ChangeDetectionStrategy.OnPush across portfolio components — the root app, floating navigation, hero section, projects grid, and every Three.js canvas wrapper. OnPush tells Angular: "only check this component when an @Input() reference changes, an event fires from its template, or a signal it reads is updated."

Signals as the Chat State Machine

The chat component (app-chat) is the heart of the real-time layer. I replaced mutable class properties with writable signals for every piece of UI state the template binds to. When a TEXT_CHUNK arrives over the socket, I call messages.update() with a new array reference — Angular flushes that to the DOM immediately under zoneless + signals. 

src/app/shared/components/chat/chat.ts// Reactive state management using Signals
public messages = signal<Message[]>([]);
public userInput = signal<string>('');
public isTyping = signal<boolean>(false);
public isReconnecting = signal<boolean>(false);
public isResetting = signal<boolean>(false);

constructor() {
  // Auto-scroll to bottom whenever the messages array updates
  effect(() => {
    if (this.messages().length || this.isTyping()) {
      setTimeout(() => this.scrollToBottom(), 50);
    }
  });

  this.geminiAI.message$.subscribe((response: GeminiResponse) => {
  // ...
  if (response.type === 'TEXT_CHUNK') {
    this.messages.update(prev => {
      const updatedList: Message[] = [...prev];
      if (updatedList.length > 0 &&
          updatedList[updatedList.length - 1].type === 'TEXT_CHUNK') {
        const lastIndex = updatedList.length - 1;
        updatedList[lastIndex] = {
          ...updatedList[lastIndex],
          text: updatedList[lastIndex].text + (response.text || '')
        };
      } else {
        updatedList.push({
          id: window.crypto.randomUUID(),
          sender: 'bot',
          type: response.type,
          text: response.text || '',
          timestamp: new Date()
        });
      }
      return updatedList;
    });
  }
  this.streamIncomingChunk();
  });
}

Why immutable updates inside update()? Angular's signal graph tracks referential equality. Mutating prev[last].text in place would not trigger a re-render. Spreading into a new object and returning a new array guarantees the signal consumer — and therefore the template — sees the change on every chunk.

Phase 2: Global State Management & Real-Time Socket Connection

I use NgRx as the single source of truth for portfolio content — skills, projects, experience, education, and project detail modals. Chat session state is intentionally not in the store; it is too ephemeral and too high-frequency for action/reducer overhead. Instead, the chat lives in component signals backed by a injectable WebSocket service.

The GeminiAi WebSocket Service

Real-time chat uses RxJS webSocket — not Socket.IO. My GeminiAi injectable opens a persistent connection to environment.WS_ENDPOINT + 'chat', deserializes JSON frames, and exposes them as an Observable the chat component subscribes to. 

src/app/services/gemini-ai.tspublic connect(): void {
  if (!this.socket$ || this.socket$.closed) {
    this.socket$ = webSocket({
      url: environment.WS_ENDPOINT + 'chat',
      openObserver: {
        next: () => {
          if (this.pendingMessage !== null) {
            this.socket$.next(this.pendingMessage);
            this.pendingMessage = null;
          }
        },
      },
      deserializer: (msg) => JSON.parse(msg.data),
      serializer: (msg) => JSON.stringify(msg),
    });

    this.socket$
      .pipe(
        retry({
          count: 3,
          delay: (error, retryCount) => timer(3000),
        }),
        catchError((error) => {
          this.handleFinalFailure();
          return EMPTY;
        }),
      )
      .subscribe({
        next: (response: GeminiResponse) => {
          this.messagesSubject.next(response);
        },
      });
  }
}

public sendMessage(payload: any): void {
  if (!this.socket$ || this.socket$.closed) {
    this.handleFinalFailure();
  }
  this.socket$.next(payload);
}

The chat UI handles four server message types:

  • WELCOME / ERROR — append a complete bot message.
  • TEXT_CHUNK — stream-append to the last bot bubble (shown in Phase 1).
  • AGENT_STEP with step: "closed" — disconnect and surface a reconnect affordance.

Phase 3: Offloading to the Background with Web Workers

Every time a message is sent or a chunk streams in, I need to persist the full conversation so a user can reopen the chat modal without losing context. Writing to IndexedDB on the main thread would block painting during long conversations — exactly when the typing indicator and scroll animations need the most headroom.

My solution: a dedicated module Web Worker (chat.worker.ts) that owns all IndexedDB transactions. The main thread sends lightweight postMessage commands; the worker replies with success/error actions.

Worker Setup in the Chat Component

src/app/shared/components/chat/chat.ts — ngOnInit()ngOnInit() {
  this.geminiAI.connect();
  if (typeof Worker !== 'undefined') {
    this.tabWorker = new Worker(
      new URL('../../workers/chat.worker', import.meta.url),
      { type: 'module' }
    );

    this.tabWorker.onmessage = ({ data }) => {
      switch (data.action) {
        case 'FETCH_SUCCESS':
          if (data.payload[0]?.raw?.length > 0) {
            this.messages.set(data.payload[0].raw);
          }
          break;
        case 'CLEAR_SUCCESS':
          this.messages.set(data.payload ?? []);
          break;
        // CACHE_SUCCESS, CACHE_ERROR, FETCH_ERROR, CLEAR_ERROR ...
      }
    };

    const workerMessageId = this.geminiAI.getItem<string>('workerMessageId');
    if (workerMessageId) this.loadHistoricalMessage(workerMessageId);
  }
}

Main Thread → Worker Communication

After every message update (user send or streamed chunk), I cache the snapshot and store the cache key in sessionStorage so the next page load can rehydrate: 

src/app/shared/components/chat/chat.tsstreamIncomingChunk() {
  if (this.tabWorker) {
    const uniqueId = 'msg_' + crypto.randomUUID();
    this.tabWorker.postMessage({
      action: 'PROCESS_AND_CACHE',
      payload: {
        id: 'msg_' + uniqueId,
        data: this.messages()
      }
    });
    this.geminiAI.setItem('workerMessageId', uniqueId);
  }
}

loadHistoricalMessage(messageId: string) {
  if (this.tabWorker) {
    this.tabWorker.postMessage({
      action: 'FETCH_CACHE',
      payload: { id: messageId }
    });
  }
}

IndexedDB Inside the Worker

The worker opens TabCacheDB with an object store named chat_cache. Each write clears the store and replaces it with the latest snapshot — a deliberate trade-off for simplicity over append-only history: 

src/app/shared/workers/chat.worker.tsconst DB_NAME = 'TabCacheDB';
const STORE_NAME = 'chat_cache';

addEventListener('message', async ({ data }) => {
  const { action, payload } = data;

  if (action === 'PROCESS_AND_CACHE') {
    const cacheEntry = {
      id: payload.id,
      timestamp: Date.now(),
      raw: payload.data,
    };
    const db = await getDB();
    await saveToCache(db, cacheEntry);
    postMessage({ action: 'CACHE_SUCCESS', payload: cacheEntry });
  }

  if (action === 'FETCH_CACHE') {
    const db = await getDB();
    const cachedData = await getAllFromCache(db);
    postMessage({ action: 'FETCH_SUCCESS', payload: cachedData });
  }

  if (action === 'CLEAR_CACHE') {
    const db = await getDB();
    await clearCache(db);
    postMessage({ action: 'CLEAR_SUCCESS', payload: [] });
  }
});

Lifecycle cleanup matters. When the chat component is destroyed, I call tabWorker.terminate() in ngOnDestroy() so the background thread does not leak across route changes. My Content Security Policy also explicitly allows workers via worker-src 'self' blob:.

Phase 4: Next-Gen Visuals with Three.js Animations

The chat console is intentionally lightweight — the visual spectacle lives in the portfolio itself. I built seven Three.js components for immersive backgrounds: an orbiting particle sphere, hero skill icons rendered as 3D sprites on a CSG parcel box, shader-driven wave particles, per-slide ambient systems, and a text-scraper animation. They share a common lifecycle contract enforced across the codebase.

SSR-Safe Initialization with afterNextRender()

Three.js touches window, document, and WebGL contexts — none of which exist during server-side rendering. I guard initialization behind isPlatformBrowser() inside afterNextRender(), and register cleanup on DestroyRef: 

src/app/shared/components/background-animation-three/background-animation-three.component.ts@Component({
  selector: 'app-background-animation-three',
  changeDetection: ChangeDetectionStrategy.OnPush,
  template: `<canvas #canvas class="background-canvas"></canvas>`,
})
export class BackgroundAnimationThreeComponent implements OnDestroy {
  private destroyRef = inject(DestroyRef);
  private themeService = inject(ThemeService);

  constructor() {
    effect(() => {
      const isDark = this.themeService.darkMode();
      const color = isDark ? this.colorConfig.dark.dot : this.colorConfig.light.dot;
      if (this.particles?.material instanceof THREE.ShaderMaterial) {
        this.particles.material.uniforms['uColor'].value.copy(color);
        this.particles.material.blending =
          isDark ? THREE.AdditiveBlending : THREE.NormalBlending;
      }
    });

    afterNextRender(() => {
      if (isPlatformBrowser(this.platformId)) {
        this.initThree();
        this.animate();
      }
    });

    this.destroyRef.onDestroy(() => this.cleanup());
  }
}

Scene Setup & Capped Pixel Ratio

I cap devicePixelRatio at 2 to prevent 4K mobile screens from melting the GPU budget, and keep particle counts conservative (140 points on the background sphere): 

background-animation-three — initThree()private initThree(): void {
  const canvas = this.canvasRef.nativeElement;
  this.scene = new THREE.Scene();
  this.camera = new THREE.PerspectiveCamera(60, aspect, 0.1, 2500);
  this.controls = new OrbitControls(this.camera, canvas);
  this.controls.enableZoom = false;
  this.controls.autoRotate = true;

  this.renderer = new THREE.WebGLRenderer({
    canvas, alpha: true, antialias: true,
  });
  this.renderer.setSize(window.innerWidth, window.innerHeight);
  this.renderer.setPixelRatio(Math.min(window.devicePixelRatio, 2));

  this.timer = new THREE.Timer();
  this.timer.connect(this.document);
  this.createParticles();
}

The Animation Loop — No Allocations in RAF

The render loop updates shader uniforms and rotation angles only — it never allocates new geometries or materials per frame. This is critical when chat streaming is simultaneously triggering signal updates: 

background-animation-three — animate()private animate(): void {
  if (!this.renderer || !this.scene || !this.camera || !this.timer) return;
  this.animationFrameId = requestAnimationFrame(() => this.animate());
  this.controls?.update();

  this.timer.update();
  const elapsedTime = this.timer.getElapsed();
  if (this.particles?.material instanceof THREE.ShaderMaterial) {
    this.particles.material.uniforms['uTime'].value = elapsedTime;
  }

  if (this.particles) {
    this.particles.rotation.y += this.autoRotateSpeed;
    this.particles.rotation.x += this.autoRotateSpeed * 0.4;
  }

  this.renderer.render(this.scene, this.camera);
}

Full Resource Disposal

Memory leaks in WebGL apps are silent killers. My cleanup() cancels the RAF handle, disposes the renderer, geometry, material, orbit controls, and timer — every GL resource is explicitly released when the component is destroyed or the user navigates away: 

background-animation-three — cleanup()private cleanup(): void {
  if (this.animationFrameId) cancelAnimationFrame(this.animationFrameId);
  this.timer?.dispose();
  this.controls?.dispose();
  if (this.renderer) this.renderer.dispose();
  if (this.particles) {
    this.particles.geometry.dispose();
    (this.particles.material as THREE.Material).dispose();
  }
  this.scene?.clear();
}

Theme changes propagate into GLSL uniforms via an Angular effect() tied to ThemeService.darkMode() — the canvas reacts to light/dark mode without reinitializing the entire scene.

Conclusion & Architectural Takeaways

Building this portfolio taught me that "personal project" and "enterprise-grade frontend" are not mutually exclusive. The combination I settled on — Angular 21 zoneless + OnPush + Signals for surgical DOM updates, NgRx feature stores for predictable portfolio data flow, RxJS WebSockets for token streaming, Web Workers + IndexedDB for off-thread persistence, and Three.js with strict lifecycle management for immersive visuals — produces an experience that feels fast, looks premium, and scales with complexity.

Five principles I would carry to any future real-time UI:

  1. Match state tooling to update frequency. NgRx for slow, shared server data; signals for fast, local UI state.
  2. Never block the main thread for I/O you can defer. Workers are not just for heavy computation — they are for any work that competes with rendering.
  3. Treat WebSocket streams as immutable event sources. Map each frame to a new signal value; let Angular's graph do the diffing.
  4. Guard WebGL behind browser checks and dispose everything. A portfolio that leaks GPU memory is worse than one without 3D at all.
  5. Enable zoneless early. It forces you to be explicit about what triggers updates — which is exactly what a streaming chat UI demands.

The result is a portfolio that does not just list my projects — it demonstrates, in real time, how I think about frontend architecture under pressure.
