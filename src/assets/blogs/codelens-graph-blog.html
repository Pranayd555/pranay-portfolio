CodeLens Graph — Knowledge & Design

A VS Code extension that indexes a codebase into a symbol graph, persists it with SQLite WASM, and exposes lightweight tools for AI assistants using MCP. This post explains the architecture, trade-offs, and the design decisions behind the parser, graph DB, and toolchain.

AI tooling VS Code extension Model Context Protocol Tree-sitter / WASM SQLite / sql.js

Overview

CodeLens Graph combines a background indexing pipeline with a lightweight graph database and an MCP server to offer safe, low-token tools for AI assistants. It is built to help agents reason about a codebase without reading the entire repository directly.

Primary features

  • Background indexing of symbols, relationships, imports, and call references
  • Persistent graph storage using `sql.js` and WASM SQLite
  • Tree-sitter grammars with a regex fallback for unsupported languages
  • MCP tools like `codelens_triage`, `codelens_search`, and `codelens_context`
  • Skill generation for AI agents and tooling that minimizes token cost

Why it exists

To make codebase analysis precise and predictable for LLMs, the extension shifts from full-file reading to a graph-driven toolset. This reduces hallucinations and helps assistants operate with only the exact symbols and references they need.

High-level architecture

The project is split into three core layers: indexing, persistence, and AI tooling. Each layer is kept modular so the extension can be extended with new languages, new graph queries, or new agent tools without rewriting the whole stack.

Parser

Uses Tree-sitter WASM grammars and a regex fallback to extract symbols, declarations, imports, and call expressions.

Graph DB

Persists nodes, edges, and call references using `sql.js`, providing a compact workspace database that can be queried quickly.

MCP and Skills

Exposes deterministic agent tools via Model Context Protocol and generates skill files to keep tool usage aligned with the graph.

Standards

The extension is designed for reproducibility: dev watch builds, a production bundle, and a standalone MCP entrypoint for CLI tool use.

Dependencies and why they matter

@modelcontextprotocol/sdk

The MCP SDK is used for exposing tool definitions and server transport so AI assistants can call graph queries deterministically.

sql.js

sqlite in WASM makes graph persistence cross-platform without native binaries, using a compact in-memory database that can be exported to disk.

web-tree-sitter + tree-sitter-wasms

These packages give the parser language-aware AST extraction, with a fallback for unsupported files to preserve robustness.

Key design decisions & trade-offs

WASM parsing over regex whenever possible

Tree-sitter delivers more accurate symbol extraction and call analysis than regex. The trade-off is bundle complexity and WASM loading, so a regex fallback is included for unsupported cases.

`sql.js` persistence instead of native SQLite

This avoids native dependencies and keeps the extension sandbox-friendly. The downside is higher memory use for large graphs, but it remains the safest cross-platform option.

MCP tools to reduce token cost

Instead of reading raw files, the extension exposes small query tools and a triage step. This design minimizes unnecessary reads and forces the agent to work from exact graph results.

Reproduce it

The repository is intended to be easy to build and inspect. The development workflow is a standard TypeScript build with watch mode and packaging support. 

npm install
npm run watch
npm run compile
npm run package

After building, run the MCP server with: 

node dist/mcp.js /path/to/workspace

Troubleshooting & common issues

  • Tree-sitter fails to initialize: ensure `tree-sitter.wasm` and language WASM files are available in `dist/wasm` or from `node_modules/tree-sitter-wasms/out`.
  • sql.js WASM path errors: the graph loader resolves `dist/wasm` first then `node_modules/sql.js/dist`.
  • Large repo memory use: limit the indexed workspace or consider a native SQLite fallback if RAM becomes a problem.

MCP triage handler
tool(
  'codelens_triage',
  'CALL THIS FIRST before any file operation or other CodeLens tool.',
  { task: z.string().describe('What you are about to do, in plain English') },
  async ({ task }: { task: string }) => {
    const r     = classifyTask(task);
    const stats = this.db.getStats();
    const next  = r.tier === 1
      ? '✅ No CodeLens call needed. Proceed directly.'
      : '→ Next: ' + r.nextTool;
    return txt([
      '## CodeLens Triage',
      'Task: "' + task + '"',
      'Tier ' + r.tier + ' — ' + r.label + ' | Cost: ' + r.cost,
      'Action: ' + r.instruction,
      '',
      next,
      '',
      'Graph: ' + stats.totalNodes + ' symbols · ' + stats.fileCount + ' files indexed',
    ].join('\n'));
  }
);
