EVA AI — Building a Grounded, Real-Time Personal Chatbot Inside My Portfolio

I did not want a chat widget that improvises my résumé. I wanted Eva — a portfolio-native assistant that answers only from my knowledge base, streams responses token-by-token, and sits inside an Angular 21 app engineered for zero-lag rendering. This post combines the full backend intelligence story and the frontend architecture that makes it feel instant.

Introduction — The Full-Stack Challenge

A high-performance AI chat interface demands two things at once: a rock-solid backend that never invents facts, and an ultra-fast frontend that renders dozens of streamed chunks per second without stuttering WebGL animations in the background.

Visitors to my portfolio are busy. A recruiter wants Angular migration details. A founder wants the Presmistique architecture story. A developer wants the CKEditor deep dive. They all land on the same page but need different slices of the same data. Eva lets them ask instead of scroll — and my engineering constraint was absolute: the agent must not hallucinate. One fabricated project detail is worse than no chat at all.

How the two halves collaborate

The Node.js backend owns Gemini Live sessions, function calling, and markdown knowledge retrieval. The Angular portfolio owns real-time UI, NgRx portfolio state, Web Worker caching, and Three.js visuals. They communicate through a strict WebSocket JSON protocol — nothing else.

Backend · Phase 1

Deterministic AI with Function Calling

My first iteration was a classic POST endpoint — you can still see the skeleton commented out in chat.routes.ts. It worked, but the real breakthrough was giving the model a single tool — searchKnowledge — and an aggressive system prompt that forbids world knowledge, inference, and fabrication. 

// src/services/gemini.service.ts
const SYSTEM_PROMPT = `
You are Eva.

You may ONLY answer using information returned by the searchKnowledge tool.

If a question requires information not present in tool results:

"I couldn't find information about that in Pranay's portfolio knowledge base."

Do not answer from your own knowledge.
Do not use world knowledge.
Do not infer. Do not guess. Do not fabricate.

Tool results are the sole source of truth.
`;

const searchKnowledgeTool: FunctionDeclaration = {
  name: "searchKnowledge",
  description: "Retrieve information from Pranay's knowledge base",
  parametersJsonSchema: {
    type: 'object',
    properties: {
      source: {
        type: 'string',
        enum: ['ckeditor5', 'ngrx', 'skills', 'experience', 'presmistique', 'projects_overview'],
      },
    },
    required: ['source'],
  },
};

The model must plan which file to read, observe the returned content, then compose an answer. I surface this loop as AGENT_STEP events — planning when the tool fires, observation when results are fed back. 

onmessage: async (message: any) => {
  if (message.toolCall?.functionCalls) {
    for (const call of message.toolCall.functionCalls) {
      onStep('planning', { message: `AI is planning to run tool: ${call.name}` });
      const result = await executeTool(call.name, call.args);
      onStep('observation', {
        message: 'Tool output received and fed back to model.',
        resultPreview: JSON.stringify(result).substring(0, 150) + '...'
      });
      await session.sendToolResponse({
        functionResponses: [{ id: call.id, name: call.name, response: result }],
      });
    }
  }
  if (message.serverContent?.modelTurn?.parts) {
    for (const part of message.serverContent.modelTurn.parts) {
      if (part.text) onTextChunk(part.text);
    }
  }
};

Token optimization through document chunking

Dumping the entire knowledge base into one prompt ballooned latency. I split documentation into domain-specific markdown files and let the model select only what it needs: 

// src/services/knowledge.service.ts
private fileMap: Record<KnowledgeSource, string> = {
  ckeditor5: 'project_ckeditor_deepdive.md',
  ngrx: 'project_ngrx_deepdive.md',
  presmistique: 'project_presmistique_deepdive.md',
  projects_overview: 'projects_overview.md',
  skills: 'skills.md',
  experience: 'experience.md'
};

async getContent(source: KnowledgeSource): Promise<string> {
  if (this.cache.has(source)) return this.cache.get(source)!;
  const filePath = path.join(__dirname, '..', '..', 'src', 'knowledge', this.fileMap[source]);
  const content = await fs.readFile(filePath, 'utf8');
  this.cache.set(source, content);
  return content;
}

Backend · Phase 2

Gemini Live & WebSocket Streaming

Once grounding was solid, the UX gap was obvious — users stared at a spinner until the full answer arrived. I upgraded to Gemini Live with persistent bidirectional sessions, using gemini-3.1-flash-live-preview and outputAudioTranscription so transcribed text streams to the chat UI. 

// src/server.ts — WebSocket upgrade with origin verification
server.on('upgrade', (request, socket, head) => {
  const { pathname } = new URL(request.url || '', `http://${request.headers.host}`);
  const origin = request.headers.origin || '';

  if (!env.allowedOrigins.includes(origin)) {
    socket.write('HTTP/1.1 403 Forbidden\r\n\r\n');
    socket.destroy();
    return;
  }

  if (pathname === '/api/chat') {
    chatWss.handleUpgrade(request, socket, head, (ws) => {
      chatWss.emit('connection', ws, request);
    });
  } else {
    socket.destroy();
  }
});
// src/controllers/chat.controller.ts — session bridge
chatWss.on('connection', async (ws: WebSocket) => {
  const connectionId = randomUUID();
  const geminiSession = await runPortfolioAgent(
    connectionId,
    (textChunk) => ws.send(JSON.stringify({ type: 'TEXT_CHUNK', text: textChunk })),
    (step, detail) => ws.send(JSON.stringify({ type: 'AGENT_STEP', step, detail })),
    () => ws.send(JSON.stringify({ type: 'TURN_COMPLETE' }))
  );
  liveSessions.set(connectionId, geminiSession);

  ws.on('message', (message: string) => {
    const data = JSON.parse(message.toString());
    if (data?.type === 'USER_MESSAGE' && typeof data.text === 'string') {
      liveSessions.get(connectionId).sendClientContent({
        turns: [{ role: 'user', parts: [{ text: data.text }] }],
        turnComplete: true,
      });
    }
  });
});

The WebSocket contract the Angular client consumes:

Event Direction Purpose
USER_MESSAGEClient → ServerVisitor question
WELCOMEServer → ClientBranded intro on connect
TEXT_CHUNKServer → ClientIncremental streamed text
AGENT_STEPServer → ClientTool planning / observation
TURN_COMPLETEServer → ClientRe-enable user input
ERRORServer → ClientConnection or parse failure

Frontend · Phase 1

Angular 21, Zoneless Change Detection & Signals

The portfolio runs Angular 21 with provideZonelessChangeDetection() globally. For a chat UI receiving dozens of WebSocket events per second, I need the DOM to update only when signals change — not on every Zone.js-patched async callback. 

// src/app/app.config.ts
export const appConfig: ApplicationConfig = {
  providers: [
    provideZonelessChangeDetection(),
    provideStore(),
    provideEffects(),
    provideClientHydration(withEventReplay()),
    // ...
  ]
};

ChangeDetectionStrategy.OnPush is applied across portfolio components. The chat console (app-chat / EVA.exe) uses writable signals for every UI-bound state: 

// src/app/shared/components/chat/chat.ts
public messages = signal<Message[]>([]);
public userInput = signal<string>('');
public isTyping = signal<boolean>(false);
public isReconnecting = signal<boolean>(false);

constructor() {
  effect(() => {
    if (this.messages().length || this.isTyping()) {
      setTimeout(() => this.scrollToBottom(), 50);
    }
  });

  this.geminiAI.message$.subscribe((response: GeminiResponse) => {
    if (response.type === 'TEXT_CHUNK') {
      this.messages.update(prev => {
        const updatedList: Message[] = [...prev];
        if (updatedList.length > 0 &&
            updatedList[updatedList.length - 1].type === 'TEXT_CHUNK') {
          const lastIndex = updatedList.length - 1;
          updatedList[lastIndex] = {
            ...updatedList[lastIndex],
            text: updatedList[lastIndex].text + (response.text || '')
          };
        } else {
          updatedList.push({
            id: window.crypto.randomUUID(),
            sender: 'bot', type: response.type,
            text: response.text || '', timestamp: new Date()
          });
        }
        return updatedList;
      });
    }
    this.streamIncomingChunk();
  });
}

Immutable updates inside signal update()

Angular's signal graph tracks referential equality. Mutating prev[last].text in place would not re-render. Spreading into new objects guarantees the template flushes on every chunk.

The GeminiAi injectable bridges the backend WebSocket contract using RxJS webSocket: 

// src/app/services/gemini-ai.ts
public connect(): void {
  if (!this.socket$ || this.socket$.closed) {
    this.socket$ = webSocket({
      url: environment.WS_ENDPOINT + 'chat',
      deserializer: (msg) => JSON.parse(msg.data),
      serializer: (msg) => JSON.stringify(msg),
    });
    this.socket$.pipe(
      retry({ count: 3, delay: () => timer(3000) }),
      catchError(() => { this.handleFinalFailure(); return EMPTY; }),
    ).subscribe({
      next: (response: GeminiResponse) => this.messagesSubject.next(response),
    });
  }
}

public sendMessage(payload: any): void {
  this.socket$.next(payload);
}

Outbound from the chat UI: this.geminiAI.sendMessage({ type: 'USER_MESSAGE', text: query }). The floating nav opens the modal via a chatOpen signal synced to a native <dialog> with an effect().

Frontend · Phase 3

Web Workers & IndexedDB Chat Caching

Every streamed chunk triggers a cache write. Doing IndexedDB I/O on the main thread competes with scroll animations and WebGL — so I offload persistence to a module Web Worker. 

// chat.ts — worker wiring
this.tabWorker = new Worker(
  new URL('../../workers/chat.worker', import.meta.url),
  { type: 'module' }
);

streamIncomingChunk() {
  const uniqueId = 'msg_' + crypto.randomUUID();
  this.tabWorker.postMessage({
    action: 'PROCESS_AND_CACHE',
    payload: { id: 'msg_' + uniqueId, data: this.messages() }
  });
  this.geminiAI.setItem('workerMessageId', uniqueId);
}
// src/app/shared/workers/chat.worker.ts
const DB_NAME = 'TabCacheDB';
const STORE_NAME = 'chat_cache';

addEventListener('message', async ({ data }) => {
  const { action, payload } = data;
  if (action === 'PROCESS_AND_CACHE') {
    const cacheEntry = { id: payload.id, timestamp: Date.now(), raw: payload.data };
    const db = await getDB();
    await saveToCache(db, cacheEntry);
    postMessage({ action: 'CACHE_SUCCESS', payload: cacheEntry });
  }
  if (action === 'FETCH_CACHE') {
    const db = await getDB();
    postMessage({ action: 'FETCH_SUCCESS', payload: await getAllFromCache(db) });
  }
  if (action === 'CLEAR_CACHE') {
    const db = await getDB();
    await clearCache(db);
    postMessage({ action: 'CLEAR_SUCCESS', payload: [] });
  }
});

Frontend · Phase 4

Three.js Visuals Alongside Live Chat

Eva's console is lightweight; the visual spectacle lives in seven Three.js components (particle sphere, hero skill icons, immersive slide backgrounds). They initialize inside afterNextRender() with SSR guards, cap pixel ratio at 2, and dispose every GL resource on destroy — critical when chat streaming fires signal updates simultaneously. 

// background-animation-three.component.ts
afterNextRender(() => {
  if (isPlatformBrowser(this.platformId)) {
    this.initThree();
    this.animate();
  }
});
this.destroyRef.onDestroy(() => this.cleanup());

private animate(): void {
  this.animationFrameId = requestAnimationFrame(() => this.animate());
  this.particles.material.uniforms['uTime'].value = this.timer.getElapsed();
  this.particles.rotation.y += this.autoRotateSpeed;
  this.renderer.render(this.scene, this.camera);
}

private cleanup(): void {
  cancelAnimationFrame(this.animationFrameId);
  this.renderer?.dispose();
  this.particles?.geometry.dispose();
  (this.particles?.material as THREE.Material).dispose();
}

Conclusion — Architectural Takeaways

EVA AI is the proof that a personal portfolio can run like an enterprise web app. The backend grounds every answer in retrievable truth; the frontend renders streams without blocking the paint thread; Docker and Nginx make it reproducible in production.

  1. Ground before you generate. Function calling + chunked knowledge eliminated hallucination as a category of bug.
  2. Stream before you wait. Gemini Live over WebSockets made follow-up questions snappy with persistent session context.
  3. Match state tooling to update frequency. NgRx for portfolio data; signals for chat; workers for I/O.
  4. Never allocate in RAF. Three.js and chat streaming share the same main thread — lifecycle discipline is non-negotiable.
  5. Containerize before you deploy. Explicit knowledge file copy in Docker saved me from silent tool-call failures in production.
